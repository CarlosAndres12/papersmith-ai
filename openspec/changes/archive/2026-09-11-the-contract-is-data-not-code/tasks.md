- **Commit-history honesty note.** The first commit of this change (`feat(paper-writing): the closed vocabulary and header schema a contract must satisfy`) already shows this file's Phase 2 checkboxes as `[x]`, even though Phase 2's own code and content landed in the SECOND commit. Both phases' work and this file's checkmarks were written together before the decision to split the delivery into four commits was made; unwinding just the checkbox text from that already-created commit would have meant amending it, which the standing instruction is to avoid in favor of always creating a new commit. The final state, from the second commit onward, is accurate; only that one intermediate commit's snapshot overstates progress relative to its own tree.
- **Real-file incident during Phase 2, already covered above at 2.3** but repeated here because it is the kind of finding this section exists for: an early version of `HeaderInsertionTests` called `install_header` with a deliberately malformed header directly against `sections/01-materials-and-methods.md` while that file was still genuinely headerless (before the real migration ran), and `install_header` at the time validated nothing before writing — so the malformed header landed on the real, tracked file. Caught immediately by the next test run, restored via `git checkout HEAD --` (the file was tracked, unmodified otherwise, and this is the one case that command is safe for), and closed at the root cause: `install_header` now calls the schema validator before any read or write of `path`, and the triggering test was rewritten to operate on an in-memory copy of the real file's bytes rather than the file itself.
